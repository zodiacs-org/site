# Consumer experience simulation — 2026-10-02

The owner approved the remaining clarity recommendations and asked for a
tester simulation. This is a browser task-completion exercise, not a study of
five human participants or evidence of retention.

## Changes

- Today: “Your daily reading and personal chart highlights.”
- Transits: “Explore today’s planets and their connections to your chart.”
- Birthday: “Find your Sun sign from your birthday, including dates near a sign change.”
- Transits and Birthday descriptions are synchronized across the shared locale
  navigation and the generated English Registry/wing navigation.
- Birth-chart startup preserves the date, time, unknown-time checkbox, house
  system, and city query entered before the calculator finishes hydrating.
  The city search then continues through the existing offline index.
- Big Three still warms its place index after mounting, through a dynamic
  import that keeps the initial JavaScript within the existing budget.

## Test method and results

Chromium 154.0.8037.58 and Playwright WebKit 26.5 ran the same five journeys
at 390 × 844 with touch enabled. A separate delayed-JavaScript regression
ran in each engine. All **12 scenario runs / 96 checks passed**.

Each journey used disposable browser storage. Calculation inputs came from
the repository's public Frida Kahlo demonstration data. The friend save used
an explicitly simulated name; mixed-owner precedence used existing fixtures.
No real account, subscriber, payment, or Guide message was submitted.

| Journey | Observed result |
| --- | --- |
| Quick horoscope visitor | Homepage → horoscope hub → Cancer reading works without a chart or signup. Back returns to the sign chooser. |
| First chart, known time | The actual form calculates, all four beginner steps advance, Save confirms device storage, and the next action opens personal Today. |
| Unknown birth time | The form accepts the unknown-time choice, omits unsupported houses/rising information, and supports Save → Today. |
| Returning visitor | Saved storage restored into a new browser context recognizes the personal chart. Back works. Advancing the clock by 24 hours retains that identity and labels the unchanged static edition with its actual date. |
| Someone else's chart | The actual Someone Else form → full chart → named save leaves the owner choice explicit. Additional fixtures confirm a newer friend edit does not replace the personal chart on Home, Today, or the default Profile selection. |

Guide opens as a compact inset sheet without focusing the composer. Hide
restores launcher focus; an unsent question survives hiding and reopening.
At a reduced height of 480px, Hide remains reachable after the viewport
resize settles. This approximates reduced available space, not an OS keyboard.
The tested pages and reading steps have no horizontal page overflow or browser
exceptions.

## Defect found and fixed

Delaying `ChartCalculator.*.js` while entering details into its visible server
form reproduced a real startup defect: hydration replaced early entries with
empty defaults. The regression failed on the birth-date preservation check
before the fix. Both engines now retain all five input values and display city
suggestions after startup. Ordinary calculation, search cancellation/recovery,
and save behavior continue to pass their existing tests.

One immediate viewport measurement initially ran before the browser's resize
event settled. The screenshot showed Hide visible; the corrected test waits
for the Guide viewport to settle. That was a test-timing issue, not a second
site defect.

## Validation and reproduction

```sh
npm run build
npm run check
CONSUMER_TEST_ENGINES=chromium,webkit OUT_DIR=/tmp/consumer-evidence npm run test:consumer:browser
npm run test:phase1:acceptance
npm run test:phase1:evidence
```

WebKit must be installed with the pinned Playwright runtime to enable that
optional engine. CI runs the Chromium journeys through `test:consumer:browser`.
The production build, typecheck, bundle budgets, 133 focused form/recovery
unit tests, and all 18 exact-width Phase 1 captures passed locally. The full
local suite has the same four pre-existing macOS failures in install behavior,
API numeric examples, scene snapshot, and wheel serialization; it passed 6,348
other tests. The complete Linux Site Check remains the release gate.

## What this cannot establish

No human comprehension, preference, or return rate was measured. Physical
iPhone/Android keyboard behavior, OS browser chrome, installed-PWA resumption,
and live Guide answer quality were not tested. A +24-hour browser clock cannot
verify tomorrow's publishing job; it checks that a static edition is not
relabeled as fresh. These results support functional continuity, not a claim
that consumers will necessarily understand every feature or return tomorrow.

The useful next evidence is an uncued first visit by real consumers and a
physical-phone return visit. No additional redesign is recommended from this
simulation.
