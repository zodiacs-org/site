# Charts, data, and embeds.
- 
Vendored candidate · engine 1.1.0-rc.2
## Calculate a chart </developers/engine/>
Quickstarts, recipes and reference guides </developers/docs/>, each with a Markdown twin.
@zodiacs/engine takes an instant and coordinates and returns bodies, angles, cusps and aspects, in your own browser or Node.js process, with no network request. What it computes, what it costs to bundle, how close it is to Swiss Ephemeris, and how to install it are on its page. The starter </developers/examples/> is the same job as a running project; it pins engine 0.1.1-rc.3, while the site runs 1.1.0-rc.2.
- 
Available · runs on our server
## Calculate on our server </developers/compute/>
Seven POST endpoints for a chart, positions, houses, the events in a window, a local time read as UTC, whether a sky fact holds, and when chosen conditions all hold, each answer with a receipt and the engine's version. No key. Birth data goes in the request body, and the function writes nothing from a request to a log, a file or a database. The endpoints answer only while their per-address rate limit is in place.
The playground </developers/playground/> sends each documented request to them, runs it in your browser with their own code, and compares the answers.
The demo </developers/demo/> asks three sample questions, a birth chart, the next Mercury retrograde and how two charts compare, and shows each answer with its JSON, the cURL command and the MCP tool call.

## Connect an AI assistant </developers/mcp/>
A local MCP server, tested with Claude Code. It calculates a chart or compares two records on your own machine over stdio. The calculation never leaves the machine; what the assistant you connect it to does with the result is a separate question.

## Compare two calculation records </developers/compare/>
When two runs of this engine disagree, this lists every value that differs and says which of them anything in the two files can actually explain. It reads the record format this site produces, not screenshots or another program's export.

## Shared sky data
The computed dates behind this site's calendars — today's sky, the weeks ahead, retrograde windows, stations, sign ingresses, moon phases, eclipses, and exact aspects — are published as versioned JSON. The files are static, cached at the edge, and open to any origin. There is no key or signup. These files contain no personal birth data: they describe the shared sky, and the site's own chart calculation stays on the device </methodology/>.
## Quick start
One request returns today's sky. No key, no account:
curl --fail --silent --show-error https://zodiacs.org/api/v1/sky/today.json
The payload opens with a summary you can read straight out, and names the edition it was computed for in date and snapshotAt. Editions change daily and delivery can be delayed, so read those fields rather than assuming the file you hold is current. Before noon, a snapshot describes positions computed for later that day.
In JavaScript, with the checks worth keeping in production:
const response = await fetch('https://zodiacs.org/api/v1/sky/today.json', {
 cache: 'no-cache',
 signal: AbortSignal.timeout(10_000),
});
if (!response.ok) throw new Error(`Sky request failed: HTTP ${response.status}`);
const sky = await response.json();
if (sky?.schema !== 'zodiacs.sky-api.today.v1'
 || typeof sky.date !== 'string'
 || typeof sky.snapshotAt !== 'string'
 || typeof sky.summary !== 'string'
 || !Array.isArray(sky.bodies)
 || sky.bodies.length === 0
 || sky.bodies.some((body) => !body
 || typeof body !== 'object'
 || typeof body.body !== 'string'
 || typeof body.position !== 'string'
 || typeof body.retrograde !== 'boolean')) {
 throw new Error('Unexpected sky payload');
}
const today = new Date().toISOString().slice(0, 10);
if (sky.date !== today) {
 throw new Error(`Sky edition ${sky.date} is not current (${today} UTC)`);
}
if (sky.snapshotAt !== `${sky.date}T12:00:00.000Z`) {
 throw new Error('Unexpected sky snapshot time');
}
console.log(`Computed positions for ${sky.snapshotAt}`);
console.log(sky.summary);
for (const body of sky.bodies) {
 console.log(body.body, body.position, body.retrograde ? 'Rx' : '');
}
This one checks the payload kind, the fields it uses, and the current UTC edition before displaying the computed snapshot.
## Sky data for AI agents
Every payload is self-describing. It opens with a summary — one or two plain sentences that state the file's facts, ready to quote — and carries an about block that defines each field and its units, a $schema link to its JSON Schema, and links to the related files. Raw numbers come with formatted twins (lon alongside position, illumination alongside illuminationPercent), and every event carries a label such as "Mercury retrograde in Scorpio, October 24, 2026 – November 13, 2026".
An agent should start at /api/v1/llms.txt </api/v1/llms.txt>: it lists every endpoint, defines every field, states the caveats worth repeating, and maps common questions ("Is Mercury retrograde?", "When is the next full moon?", "When does the Sun enter Libra?") to the file and field that answer them. Tool-calling frameworks can load /api/v1/openapi.json </api/v1/openapi.json> directly, and the daily files have Markdown twins for readers that fetch pages as text.
## Daily endpoints
- /api/v1/sky/today.json
Today's positions for the Sun, Moon, and eight planets (raw longitudes and formatted labels like 14°53′ Virgo), moon phase and illumination, the active retrograde windows, the next new and full moon with signs and traditional names, the day's exact events, and a plain-language summary. Positions are a 12:00 UTC snapshot. Daily publication is scheduled from 00:00 UTC; check the payload date because delivery can be delayed.
- /api/v1/sky/upcoming.json
Every lunation, sign ingress, station, eclipse, and exact aspect in the next 60 days in order, plus the next occurrence of each kind and the current and next Mercury retrograde.
- /api/v1/planets/{sun|moon|mercury|venus|mars|jupiter|saturn|uranus|neptune|pluto}.json
One body: position at the daily snapshot, whether it is retrograde, its current and next retrograde window, every window in coverage, and its next sign ingress and station.
- /api/v1/signs.json
The twelve signs: element, modality, ruler and traditional ruler, polarity, house, conventional dates, the computed Sun season for this year, and which bodies occupy each sign today.
## Yearly endpoints
- /api/v1/retrogrades/{2026–2030}.json
Retrograde windows intersecting the year: retrograde and direct station instants and signs, pre- and post-shadow boundaries, duration, and clipping flags where the data boundary truncates a window.
- /api/v1/stations/{2026–2030}.json
Every station — a planet turning retrograde or direct — with its sign and degree.
- /api/v1/ingresses/{2026–2030}.json
Every planetary sign ingress, with the exact instant and whether the planet entered moving retrograde.
- /api/v1/moon-phases/{2026–2030}.json
Every new and full moon with sign, degree, and the traditional full-moon name (Blue for a second full moon in one month).
- /api/v1/eclipses/{2026–2030}.json
Solar and lunar eclipses by instant of greatest eclipse: type, kind, sign, obscuration, and totality length.
- /api/v1/aspects/{2026–2030}.json
Exact planetary aspects (orb 0) across the year, each with a label such as Mars square Saturn.
## Documents and schemas
- /api/v1/llms.txt
The guide for AI agents: every endpoint, every field, the caveats worth stating, and which file answers which question.
- /api/v1/openapi.json
OpenAPI 3.1 with every JSON Schema embedded, for tool-calling frameworks and typed clients.
- /api/v1/schema/{name}.v1.json
Each payload family's JSON Schema (draft 2020-12); every payload links its own under $schema.
- /api/v1/sky/today.md and /api/v1/sky/upcoming.md
The daily files rendered as Markdown for readers that fetch pages as text.
- /api/v1/index.json
Every endpoint and document above, with coverage and the data vintage.
## The contract
Positions are apparent geocentric tropical longitudes from the same engine the calculators use, tested against NASA JPL Horizons reference data at two dates, 1907 and 2020, where the largest difference is 14.8 arcseconds. Today's positions are a single snapshot taken at 12:00 UTC (snapshotAt). Publication is scheduled from 00:00 UTC; jobs, deployment, or caches can delay availability. All instants are UTC in ISO 8601, and signs are lowercase slugs with an English signName beside them.
A retrograde window's from and to are its stations unless clippedStart or clippedEnd is true, which means the data boundary truncated the window and the real station lies outside coverage. Within v1, fields are added, never renamed or removed; a breaking change would ship under /api/v2/ and v1 would keep working. Yearly files are byte-stable between data refreshes, so conditional requests are cheap. Year files cover 2026–2030 today and grow as the underlying data is extended; read index.json </api/v1/index.json> rather than assuming which years exist.
## Freshness and caching
Check the file you consume: date identifies the UTC edition for today's sky, planet files, and signs; snapshotAt is its noon snapshot. Upcoming events use from as the snapshot instant. generatedAt records the file build time and can change without a new edition. The index's coverage.dailyDate describes the index; separately cached files can have different dates. Label an older edition by its date or wait for a current one before presenting it as today's sky.
Current cache lifetimes are 300 seconds for sky/today.json, 3,600 seconds for index.json, and 86,400 seconds for the remaining API files, including upcoming events, planets, signs, and Markdown twins. Revalidation can refresh a cached response; always check its edition date as well. Yearly files remain byte-stable between data refreshes.
