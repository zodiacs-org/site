# Site adoption of engine 1.0.0

Base: site main `073bde6e27b2d302352ba056f8ee3fd65f03446e`. This revision vendors
`@zodiacs/engine@1.0.0`, the first stable release, which npm publishes under
`latest`. It also carries MCP adapter 0.1.0-rc.19 and developer plugin 0.3.7,
both built on it. The record ends with what is not established here.

## The archive and its publication

[ARTIFACT-IDENTITY.md](ARTIFACT-IDENTITY.md) binds `vendor/zodiacs-engine-1.0.0.tgz`
to the engine carrier `38d31854`. The archive is 288,063 bytes, SHA-256
`c4d3754d…b0f6`; source `ca2c8cef`, merged by `f8992a4c` (zodiacs-org/engine#39).

The site's registry tool read npm's record on 2026-10-11
([npm-registry.json](npm-registry.json)):

- `latest` is 1.0.0;
- npm's tarball is this archive;
- the SLSA provenance names the engine's `release.yml` on main at `f8992a4c`;
- `npm audit signatures` verifies the attestation.

The lockfile's SHA-512 integrity is npm's. The lockfile changes in four lines:
the dependency, version, `resolved` and `integrity`. Every earlier archive
keeps its bytes.

1.0.0 is 1.0.0-rc.2 with the version changed.
[entry-graphs.txt](entry-graphs.txt) follows each of the 14 public entry
points through its static imports in both archives. Each loads the same code,
apart from the quoted version literal and the hashed chunk names
(`tools/compare-entry-graphs.mjs`). Nothing the site computes changes. The
version string, digests over it, and records that name the engine do change.

## Platform

Five monthly transit files regenerated here differ in one value each, by
5.7e-14° to 1.1e-13° (one station, four aspect degrees). This machine is
arm64, and its V8 arithmetic differs from x86-64's in the last bits (site
FINDINGS F-82). The code is unchanged, so x86-64 reproduces the base bytes,
and those are kept.

The same happens in three other places, handled the same way:

- **Reference builder.** Two fixtures changed five values in the tenth
  decimal. Only the version change is applied, and the four digests are exactly
  the version-only ones.
- **Compute examples.** Both lunar nodes' speeds differ by 5.7e-9°/day, the
  libm variance the test bounds. The documented values are kept. Receipts hold
  no results, so the cite digests stand.
- **Parity reports.** Two of their 28 residuals differ from rc.2's x86-64
  report, by at most 1.1e-13°/day; they are a measurement on this platform.

CI runs on x86-64. Three of its checks confirm the kept bytes: the
independent-references job rebuilds and diffs the fixtures, the daily verify
recomputes, and the examples test compares exactly.

  `llms-full` check now require the version to stand alone, because "1.0.0" is

  digest through the rc.2 adoption; it now names the current one.

  takes the engine identity from the site's candidate record instead of
  hard-coding rc.2.
  - Its four reports must still equal the retained rc.2 reports byte for byte,
    so any numerical change fails.
  - `validation.json` may now differ in its producer and engine identity.
  - Its self-test passes 17 of 17, including a new control.
