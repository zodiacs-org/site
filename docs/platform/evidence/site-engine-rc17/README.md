# Engine rc.17 adoption

The site moves from `@zodiacs/engine` 0.1.1-rc.16 to 0.1.1-rc.17, the
release candidate that adds the sidereal zodiac to `@zodiacs/engine/calc`.
The site imports neither `./calc` nor `./vedic`, the two entries rc.17
changes, and everything it computes is what it computed with rc.16. rc.17 is
not on npm and, under the owner's delegated decision of 2026-10-05
([DECISIONS-2026-10-05.md](../../programme/DECISIONS-2026-10-05.md) §7), will
not be: the next publication is the 1.0 candidate.

Source commit `aae419c05b77455b9e8f03ca11ee273b446f7d02`, carried by
`b080217c1b5b0b36c931e9c237bcff0308ec1efc`, both on the engine's main since
engine pull request #26 was merged (`782b4963a8575fa8d81c602a36285f65fb9ae9bb`):
https://raw.githubusercontent.com/zodiacs-org/engine/b080217c1b5b0b36c931e9c237bcff0308ec1efc/artifacts/zodiacs-engine-0.1.1-rc.17.tgz

SHA-256 `9cd24c788863424ef614aaadec580db5a0dfc529303d385274db48a092a5299a`;
273,123 bytes, 70 files, 946,349 bytes unpacked.
`vendor/zodiacs-engine-0.1.1-rc.17.tgz` is the carrier's git object byte for
byte, and the lockfile's integrity is its SHA-512. The rc.16 archive and the
earlier ones stay in `vendor/` with their bytes.

## npm

On 2026-10-06 npm lists rc.14, rc.15 and rc.16, with rc.15 under `latest`
and rc.16 under `next`; rc.17 is not in the registry
([npm-view.txt](npm-view.txt)). The registry read of rc.16
([npm-registry-rc16.json](npm-registry-rc16.json), made with rc.15's tool,
`../site-engine-rc15/tools/npm-registry-read.mjs`) shows that npm's tarball
is the rc.16 archive in `vendor/`, by SHA-1 and SHA-512, and
`npm audit signatures` verifies its attestation.
`src/data/platform-engine-candidate.json` records rc.17 as a vendored
candidate and rc.16 as the version npm serves, and the developer pages
follow it: they install rc.17 from its carrier, and say that installing
from npm gives rc.16, which refuses the sidereal zodiac in `./calc`.

## What changes for the site

- **The entries it imports.** The site imports the root entry,
  `./receipt`, `./techniques`, `./internal`, `./internal/math`,
  `./deltat`, `./geo` and `./crossings`. Each loads rc.16's files, byte
  for byte or apart from content-hashed chunk names and the version string;
  only `./calc` and `./vedic` differ ([entry-graphs.txt](entry-graphs.txt),
  made on the two archives in `vendor/` with the engine's own comparison
  tool).
- **Data the generators write.** Every file the engine-derived generators
  write, 60 transit months and 11 others, was regenerated with rc.16 and
  with rc.17 and compared with site main
  ([regenerated-outputs.json](regenerated-outputs.json),
  [tools/regen-engine-data.sh](tools/regen-engine-data.sh)). Sixty-seven
  are identical in all three. Three differ only in the time stamp of the
  run, and the committed files are kept. `daily-publication-manifest.json`
  differs under rc.17 in the engine version it names and in its generator
  digest, which covers `package-lock.json`; that file is committed. The
  dependency audit fix that followed in the same pull request (smol-toml,
  source-map-js and tinypool) changed the lockfile, and so that digest
  again: the committed manifest is that later one, with the same facts.
- **Reference fixtures and snapshots.** The four independent-reference
  fixtures in `src/lib/engine/fixtures/`, rebuilt by
  `docs/engine-validation/independent-references/tools/build.py` from the
  Horizons responses kept in the repository and the installed engine, and
  the Kahlo scene snapshot change only in the engine version they record.
  The fixtures' digests, pinned in `engine.test.ts`, `lunar-return.test.ts`,
  `transit-window-independent.test.ts` and
  `scripts/platform-engine-report.mjs`, move with them.
- **Conformance.** `src/data/conformance/summary.json` is copied from the
  engine's main at `782b4963`. It differs from rc.16's in the engine version,
  in two places; the 500 verdicts and residuals are rc.16's.
- **Compute API.** The bundle differs from main's in six lines: the version
  string and comments naming chunk files. The reviewed-input digest changes
  after a fresh private-state audit ([PRIVATE-STATE.md](PRIVATE-STATE.md)).
  `src/lib/compute-api/examples.json` was regenerated by
  `scripts/build-compute-examples.mjs` on Node 22.23.3: it changes in the
  engine version, the receipt digests that cover it and the runtime's time
  zone database (2026c, where the last run's Node had 2026b). The OpenAPI
  test, which sets the runtime's own versions aside, passes on Node 22.22.2
  and 22.23.3.
- **Time basis.** `src/lib/engine/time-basis.mjs`, rebuilt from rc.17,
  differs in five comment lines, and `scripts/build-time-basis.mjs --check`
  passes.
- **Sizes.** `src/data/engine-bundle.json` changes in its version and in one
  figure: the natal chunk's Brotli size, 29.8 KB to 29.7 KB.
- **Swiss statistics.** The multiyear and ΔT comparisons give rc.16's
  numbers ([accuracy-refresh/README.md](accuracy-refresh/README.md)).
- **Node parity and the packed consumer.** The node and polar checks give
  rc.16's values for every case on Node 22.22.2 and 24.21.0
  ([node22](node22-parity.json), [node24](node24-parity.json)); their
  fixture digest differs because the fixture records the engine version.
  The engine's packed-consumer harness passes on both runtimes
  ([public-candidate-consumer.log](public-candidate-consumer.log)). The
  engine's own record of rc.17 has its packed consumer passing on this
  archive on Node 20.19.0, 22.7.0, 22.22.2 and 24.21.0 (the engine
  repository's `docs/evidence/rc17-20261005/README.md` at `782b4963`).
- **The sky-fact benchmark.** v0 was drawn with rc.16. With any other
  engine its generator refuses to draw or check it, and
  `tests/benchmarks/sky-benchmark.test.ts` holds v0 to its pinned bytes
  rather than to a fresh draw, and does not run the one test that needs
  v0's own engine: every rule and margin v0 publishes, derived again from
  that engine. With rc.17 installed, that test is the one the full suite
  skips. To see what those checks would find, v0 was drawn again on rc.17
  by the generator's own steps, without the refusal
  ([sky-benchmark-v0/redraw-rc17.json](sky-benchmark-v0/redraw-rc17.json),
  [tools/redraw-sky-benchmark-v0.mjs](tools/redraw-sky-benchmark-v0.mjs)):
  `items.json` is the same bytes; `key.json` differs only in the engine
  version it names; and the 300 replies in `tool-answers.json` differ only
  in the version they name and the receipt digest over it, so the
  generator's own check finds no reply that differs. A temporary copy of
  the test that read the installed engine as v0's ran the two tests that
  depend on v0's engine on rc.17, and both passed
  ([engine-gate.diff](sky-benchmark-v0/engine-gate.diff),
  [engine-gate-tests.log](sky-benchmark-v0/engine-gate-tests.log)). v0
  keeps its bytes.
- **The MCP adapter.** `zodiacs-mcp-server` 0.1.0-rc.17 bundles rc.17, and
  its `get_capabilities` labels the engine `unpublished-candidate`, where
  rc.16.1 to rc.16.3 labelled rc.16 `published` on npm. Driven with the same
  tool list, both resources and 278 tool calls, ten of them refusals, it
  answers as rc.16.3 does apart from that label, the versions and the
  digests over receipts that name them
  ([mcp-rc16.3-rc17.json](mcp-rc16.3-rc17.json),
  [tools/compare-mcp-versions.mjs](tools/compare-mcp-versions.mjs)). The
  protocol drive and the archive's own install check expected the
  published label and failed against this bundle; each now reads the label
  from a candidate record. The drives and a fresh install of the archive
  pass; the adapter's record lists them
  ([`../mcp-adapter/README.md`](../mcp-adapter/README.md), section
  0.1.0-rc.17). rc.16.3's archive keeps its bytes.
- **The engine API reference.** `public/developers/engine/reference/` is
  generated again from rc.17's declarations, and
  `node scripts/build-engine-reference.mjs --check` reproduces it. Four new
  pages and seven changed ones document the sidereal zodiac in `./calc`
  (its zodiac and ayanamsa types, and the fields that report the ayanamsa);
  the index names the archive it is built from rather than a released
  package. Every other page changes only in the version and source it names
  and in TypeDoc's internal reflection numbers, and the release notices are
  rc.17's.

## What is not established

- rc.17 is not published, and nothing here publishes it.
- The site, the compute API and the MCP adapter do not offer the sidereal
  zodiac. Adding it to the adapter's tools is a separate unit
  (DECISIONS-2026-10-05.md §6).
- While the site runs rc.17, the test suite does not derive the sky-fact
  benchmark v0's rules and margins again: that test runs only with the
  engine v0 was drawn with. The run on rc.17 above was made once, on
  6 October 2026, and the suite does not repeat it.
- No programme unit is accepted by this adoption. P3.2 (the uniform
  calculation API) is judged at the next checkpoint, once production serves
  this revision.
- These are local checks. Production is verified after the merge.
