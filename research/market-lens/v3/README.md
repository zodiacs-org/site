# Expanded prospective paper study v3 — blocked draft

This is a separate, reviewable runtime and protocol. Nothing here edits or activates v1/v2. No dates are frozen, no live v3 receipts have been created, and no benefit is claimed.

`protocol-draft.json` fixes the proposed method, candidate set, costs by class, session and corporate-action policy, cash ETF exposure instead of reference indexes/futures, native-currency reporting and descriptive treatment of correlated assets/multiple comparisons. Activation is refused while `status` is `draft-blocked`. The final eligible set must be fixed **before** outcomes, using dated constituent and measured liquidity evidence; missing provider coverage must not be resolved by choosing historical winners.

## Activation prerequisites

Obtain written rights, secure provider credentials, provider-verified symbol/currency/tick/lot mappings, an acquisition acceptance receipt, dated eligibility/liquidity evidence and a provider-aligned complete session schedule (50 warmup sessions plus the entire 180-day window) for each included instrument. Session objects are `{id,open,close,adjustmentBreak?}`, Unix seconds. Freeze a new start at least two days in the future only after the complete private acquisition/scheduler/restore acceptance passes. The runtime checks these prerequisites structurally; an operator must verify the underlying contract and source evidence. A hash string alone is not proof of licensing.

FX requires an explicit provider-aligned daily cutoff, including Sunday/holiday short sessions; do not use the NY17 planning convention for a different vendor's UTC bars. Overseas calendars and variable tick tables are still awaiting verified source snapshots. Futures are excluded, not silently rolled or treated as ETFs. If futures become necessary, write another protocol with expiry, margin and deterministic roll rules.

## Runtime contract

`runtime.mjs` validates protocol/snapshot/session identities, selects the latest 50 consecutive finalized sessions at recording time, calculates the pinned rc.17 lunar gate at future execution, and settles with fixed adverse tick rounding, lots and two-sided costs. The last eligible finalized session can precede the immediately previous execution session, particularly for 24-hour markets. No feature from a currently open or future bar is accepted. Corporate-action breaks restart the 50-session warmup. Missed, unsettled or unwitnessed sessions remain visible. Reports show every asset independently in quote currency; there is no USD conversion or pooled independent-sample inference.

`scripts/market-lens-paper-v3.mjs` provides `freeze`, `record`, `witness`, `settle`, `report`, `backup`. Use an isolated private `--dir` outside the public checkout. Record/settle take a private `--input` acquisition JSON with exact `instrument`, `provider`, `symbol`, `currency`, `receivedAt` and normalized finalized `candles`. Receipt files use exclusive creation and content hashes. Queries, responses, CA identity and decision digest are checked with OpenSSL; a partial timestamp failure is preserved for review, never overwritten or retrospectively attested. Source hashes are verified on every operation. Backups include separate state/ and frozen/ directories, runtime source, vendor tarball, preserved CA and a pinned minimal dependency lock; `restore.py` checks the companion SHA-256, refuses links/traversal/duplicates and restores only into a new directory.

`scripts/market-lens-v3-acquire.ts` connects the real site adapters to private acquisition files. `node scripts/build-market-lens-v3.mjs` produces the standalone `acquire.mjs` included in the source seal and backup. It retains exact successful vendor response bytes, hashes and the normalized dataset outside the public checkout; credentials/headers are never included. Frozen provider, currency, sessions and corporate-action boundaries must match. `MARKET_LENS_V3_PRIVATE_ACQUISITION_ENABLED=1` is an additional explicit private activation gate; it does not confer rights.

`cycle.mjs PRIVATE_STATE` serializes runs with an exclusive lock, records/witnesses sessions 15–60 minutes before opening, settles due recorded sessions, reuses immutable receipts and appends a report. No missing historical decision is backfilled. Configure a private scheduler every 15 minutes only after live acceptance; preserve and inspect a crash lock rather than removing it automatically. Run `backup` after each cycle even when it fails, persist append-only state and publish only private recovery artifacts. The complete minimal source package includes the acquisition bundle and scheduler; no archived full-site install is required.

**Activation remains blocked** by actual written rights, credentials, accepted symbol/action/calendar/eligibility inputs and an end-to-end live acquisition/timestamp/scheduler acceptance receipt. The code and synthetic scheduler/recovery tests do not establish those external facts. The v2 workflow continues independently.

## Recovery acceptance

Freeze source, vendor engine tarball and minimal dependency lock. Install only engine/astronomy dependencies (not the archived site lock). The recovery package includes the preserved trusted timestamp CA. Verify source and protocol hashes, every decision/settlement linkage and both query/digest timestamp checks on the restored state. Repeated report/witness verification must preserve original bytes. Retain a second offline archive outside GitHub and exercise restoration before issuing the first live decision. The v3 tests cover deterministic calculations, refusal boundaries, actual CLI freeze/backup, safe restore, source byte equality and refusal of overwrites/tampered archives; real provider and full scheduler acceptance remain prerequisites, not claimed passes.
